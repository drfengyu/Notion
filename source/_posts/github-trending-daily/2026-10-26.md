## 1. [Nutlope/hallmark](https://github.com/Nutlope/hallmark)
- **语言**：CSS
- **总 Star**：33,800
- **当日新增**：+1,317/天
- **简介**：Together AI 出品的「反 AI 味」设计 skill，供 Claude Code、Codex、Cursor、OpenCode 调用，核心主张是"守住硬底线然后别挡路"：从 48 套主题（每套是一个 ≤8 KB 的单文件，配一张成品页截图，构建时只读其中一套）里发三套供选择，围绕访客要完成的任务排版，再在真实浏览器里 lint 那些一眼假的特征——每个小标题上方的 eyebrow、拉开字距的全大写标签、标题里孤零零的一个彩色词、整页空框或纯图片堆砌、撑不满屏幕的 hero、每页末尾都有的邮件订阅、点了"谢谢"却什么都没提交的表单。门禁分三层：Floor（对比度、焦点、reduced-motion、编造事实、手机端布局坏）永不放行，Reflex（模型默认爱掉的套路）可在有理由并留档时越权，Finish 只做工艺提示不阻断发布；v2 另加 755 张按主题挑选、页面署名授权的开放许可照片，以及 `/hallmark redesign <path>`（保留内容与接线重排）与 `/hallmark audit <path>`（只报告不改）。2026-04-27 创建，MIT，1,767 fork，最近一次推送 2026-10-22，官网 usehallmark.com。
- **亮点**：它把"审美"这件原本只能靠人眼主观判断的事，拆成了可执行的门禁清单——真正可复用的是那条 anti-pattern 列表和"最后由一个无上下文 reviewer 拍板"的流程，而不是 48 套配色，这也解释了为什么一个 skill 仓库能吃下 CSS 语言标签和当日全榜第一的增量。对做 agent 前端的团队，可直接借鉴的是分层思路：把不可妥协项（可访问性、移动端破版、事实性）设成 CI 级硬失败，把风格偏好设成可留档豁免。局限也要看清：它作用在提示与校验层，不绑组件库、不进构建链，因此效果强依赖所用模型的行为，换模型版本后需重跑一遍基准页；且"lint in a real browser"意味着需要截图/浏览器环境，接入到无头流水线时成本要先估。

## 2. [makecindy/cindy](https://github.com/makecindy/cindy)
- **语言**：TypeScript
- **总 Star**：4,883
- **当日新增**：+675/天
- **简介**：开源、开箱即用的本地 AI Agent 客户端（口号"想到，就能做到"），本仓库是 Apache-2.0 的**客户端**：Electron 桌面 + Expo/React Native 移动，pnpm monorepo（`apps/desktop`、`apps/mobile`、`packages/*` 放鉴权、设备互联、agent 编排、模型 provider 等共享能力），后端服务在另一个不开源的仓库。运行在你自己机器上、用真实文件和已登录应用，第一方接的两个 harness 是 Claude Code 与 Codex（原生 harness 在路上），harness × model 可自由混搭并在任务中途切换而保持 workspace、memory、skills、tools 连续，一个任务能由不同组合分别规划、并行执行与复核；能驱动浏览器、电脑和手机，也能从 IM 与日程接活。模型侧四条路：登录官方托管服务按量扣、授权使用你已在付费的 Claude Code / Codex Coding Plan（不重复计费）、自带 API key、或接本地模型；不想登录可在登录页选 Skip Sign-In 只用本地 agent（服务端能力随之不可用）。2026-07-22 创建，4,883 star / 666 fork / 1,919 未关闭 issue，发版节奏接近每日（v0.1.115 于 2026-10-23，前一日 v0.1.114）。
- **亮点**：定位很清楚——不是又一个 CLI agent，而是把"多 harness 编排 + 桌面移动双端 + 记忆/技能/MCP/插件可扩展"做成一个能直接用的产品壳，并把你已付的 Coding Plan 复用作获客点，这条"订阅复用"路径在同类产品里少见。评估时有三处要落地确认：其一，仓库把 claude-code、codex、ripgrep 等工具二进制交由 `pnpm install` 按平台下载（Windows 打包还额外拉带 sha256 校验的 Android platform-tools），企业环境要按"安装期拉取外部二进制"走供应链审查；其二，1,919 个未关闭 issue 加上 0.1.1xx 的日更版本号，意味着行为面还在快速变动，接入内部流程前宜锁版本；其三，可自托管的只有客户端，服务端能力闭源，因此"开源"不等于能完全离线自建。

## 3. [pollen-robotics/microduck](https://github.com/pollen-robotics/microduck)
- **语言**：Rust
- **总 Star**：11,655
- **当日新增**：+647/天
- **简介**：约 25 cm、800 g 的双足"鸭子"机器人，本仓库是它的大脑：Rockchip RK3566 上跑一组 Rust daemon，50 Hz 控制环用神经网络策略驱动十五个舵机及遥控与相机。分工是 `robotd`（控制环与电机总线）、`updaterd`（安装签名版本、启动后不健康即回滚）、`configd`（wifi 与身份）、`btd`（手机走的蓝牙通道）、`padd`（手柄）、`mediad`（WebRTC 推流）、`tofd`（深度传感器），彼此只在 Unix socket 上走同一份 JSON-RPC 契约——App、控制台、手柄、你的脚本发的调用完全一致。策略不在本仓库训练，而在隔壁 `microduck_rl`（MuJoCo + PPO + domain randomisation，导出 ONNX 由本仓库加载）；没有实体机器人时 `scripts/duck-sim` 可以让真实 daemon 对着 MuJoCo 里的身体跑，单窗口一只或当四台机器登录。功能面已演示：行走、装轮切换 roller 模式换"另一副大脑"、喙到地面一键捡物、被推倒自己站起、坐、踢球、按指令前进、叫 own 的声音。Apache-2.0，2026-07-29 创建，11,655 star / 1,483 fork，最近推送 2026-10-25。
- **亮点**：抛开"鸭子"的传播属性，这份代码对嵌入式/机器人团队最值钱的是几条工程纪律：OTA 被做成 daemon 职责且"每次更新可验证、健康门禁、可回滚"，训练与运行时彻底分仓（RL 仓只产 ONNX，设备侧不碰训练依赖），无框架、单 workspace 的 Rust 栈把控制环这类时序敏感部分和外围服务隔离开，`docs/design/` 写"为什么是这样"、`docs/project/` 写"哪里出过问题、要什么条件才能关闭它"。把同一套 RPC 契约同时供 App、手柄和脚本使用，也是设备类产品少见的克制——意味着自动化测试与人工操控走的是同一条路。要真用起来还得看硬件：整机需从其官网购买，策略与固件仍在 `daemon-dev-*` 这类开发分支命名的 release 上滚动，二次开发预算要按"仍在快速变动"估。
