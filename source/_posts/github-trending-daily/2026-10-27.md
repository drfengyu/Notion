## 2. [alchaincyf/huashu-design](https://github.com/alchaincyf/huashu-design)
- **语言**：HTML
- **总 Star**：26,877
- **当日新增**：+251/天
- **简介**：Huashu Design 3.0，一个跨 agent 通用的「设计技能」：在 Claude Code / Cursor / Codex / OpenClaw / Hermes 里打一句话，产出网页、可点击 App 原型、可编辑 PPTX、动画与信息图。3.0 的机制是先把流程拆开而不是把 prompt 写得更长——先出 6 张缩略图再从里面挑 3 个方向做成真稿；风格库扩到 84 种且每种都带样张（新增 App、中文与东亚两个分区）；找现实参照时先用 `ref_board.py` 把参考产品截成参考板再动手；配一个「只量事实」的设计体检（例：两版首屏都用了《神奈川冲浪里》，它就把暗场那版换成《山下白雨》）；再加一本「外观账本」记住你上一个项目长什么样，避免所有产出趋同。安装为 `npx skills add alchaincyf/huashu-design`。2026-04-19 创建，自 2026-05-14 起改为 MIT（个人与商用均免费、无需事先授权，原「企业商用需授权」条款作废），2,969 个 fork，最后一次推送 2026-10-23。
- **亮点**：值得借鉴的是它把「AI 设计一股 AI 味」当成可检查的工程问题来解：先出多个方向再执行、动手前必须有参照板、用体检脚本查撞车、用账本防同质化，这四步都独立于模型能力，换任何 agent 都成立。风险在证据链：README 声明「你看到的每一页都是它自己做的」，属自我证明，真要用于交付建议拿自己的品牌资产（logo、色板、UI 截图）实跑一轮再判断；仓库体积 229 MB，大量是样张资源，clone 前可留意带宽与 CI 缓存。

## 3. [gitroomhq/postiz-app](https://github.com/gitroomhq/postiz-app)
- **语言**：TypeScript
- **总 Star**：38,502
- **当日新增**：+188/天
- **简介**：开源的社媒内容排期与运营平台：多平台统一排期发布（内置 AI 能力）、数据看板做效果分析、团队协作为帖子评论与交接，并提供 Public API 与 NodeJS SDK、n8n 自定义节点、Make.com 集成等自动化入口；有 Postiz Cloud 托管版和自托管开源版两条路。技术栈为 pnpm workspace monorepo + NextJS(React) 前端 + NestJS 后端 + Prisma（默认 PostgreSQL）+ Temporal 做工作流 + Resend 发通知，仓库另有 `@postiz/node` SDK 包。2023-07-08 创建，AGPL-3.0，7,458 个 fork、222 个未关闭 issue，最后一次推送 2026-10-24。合规上官方明确：托管版只走各平台经批准的 OAuth 流程，不自动化、不爬取社媒内容，不收集也不代理用户的 API key 与 token，用户始终直连平台认证。
- **亮点**：那份「只用官方 OAuth、不碰爬取」的边界是它能长期公开传播的关键——同类社媒自动化工具大多靠浏览器模拟或逆向接口，随时面临封号与法律风险，它把产品做在平台合规一侧。另一面是 AGPL-3.0 的网络条款：自托管并对外提供服务、又改了源码，就要按许可证开放修改版，做闭源 SaaS 前必须评估这一点；选它更适合内部运营工具或愿意接受 copyleft 的场景，而非直接包装成商业产品。

## 4. [nightly-labs/openbot](https://github.com/nightly-labs/openbot)
- **语言**：TypeScript
- **总 Star**：1,524
- **当日新增**：+176/天
- **简介**：local-first 的桌面「AI 同事」工作台：一个 app 里同时跑多家的编码 agent，支持本地 Codex App Server 与 Claude Code，并通过 ACP 协议接 Grok CLI、OpenCode、Gemini、Cursor CLI、Cline；每个 agent 有独立工作区和独立会话，应用层提供 FIFO 消息队列（暂停/恢复/取消、崩溃可恢复）、agent 间文件传输、内嵌浏览器、agent 互发消息，还支持自定义 OpenAI 兼容端点、自定义 ACP agent 以及自动探测本地模型服务（Ollama、LM Studio），并按 agent 监控上下文长度、在撑爆模型窗口前自动压缩。架构上 Electron main 负责生命周期与 IPC，本地经 stdio JSONL 连 Codex App Server、经 stream JSON 连 Claude Agent SDK，用 SQLite 存命令日志与只读投影，渲染层是 SolidJS；云端账号体系跑在 Cloudflare Workers（TanStack Start + Solid 2，D1 存账号/邮箱验证/哈希会话/团队隧道，R2 存头像）。开发需 Bun 1.4.2 与 Node 24。2026-08-12 创建，最后一次推送 2026-10-26 深夜，189 个 fork、202 个未关闭 issue；许可证为 PolyForm Noncommercial 1.0.0（GitHub API 因非 OSI 标准而显示 NOASSERTION）。
- **亮点**：它赌的是「多 agent 并行 + 本地持久化」会成为日常，所以真正的工程量在编排层而非模型层——队列、上下文压缩、跨 agent 文件与消息、崩溃恢复，这些正是把几个 CLI 拼在一起时最缺的部分。但 README 顶部的警告必须先看：当前 agent 以 `danger-full-access`、`approvalPolicy: never` 运行，首次启动同意之后就能无逐条确认地读写文件、执行命令、联网并操控内嵌浏览器，官方直说「完整本地访问是当前的产品决策，不是安全边界」；叠加 PolyForm 非商业许可，它现阶段是给人尝鲜的技术预览，公司环境落地要等权限模型和许可两条线都松动。
