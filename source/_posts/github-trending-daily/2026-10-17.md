## 1. [MadsLorentzen/ai-job-search](https://github.com/MadsLorentzen/ai-job-search)
- **语言**：Python
- **总 Star**：48,569
- **当日新增**：+898/天
- **简介**：一个跑在自己机器上的 AI 求职框架，基于 Claude Code 搭建，覆盖「评估岗位匹配度 → 按岗位定制简历 → 写求职信 → 准备面试」这条完整链路，作者明确鼓励直接 fork 下来改成自己的版本（Fork it and own it）。
- **亮点**：这类项目值得关注的不是「AI 帮你投简历」的噱头，而是它示范了一种把长流程个人事务沉淀成可复用 agent 工作流的做法：岗位 JD、个人经历、过往投递反馈都在本地，模型只负责按模板做匹配与改写，人保留最终发送权。用它要留意两点：一是简历措辞被模型抹平后容易失去个人特征，HR 一眼能看出「AI 味」，产出仍要人工改写一遍；二是把身份证号、住址、完整工作经历交给第三方模型前得先确认数据去向，敏感字段建议本地脱敏后再进上下文。反过来说，它对「批量投递即垃圾邮件」的现实是个提醒——工具降低的是投递成本，不是雇主的筛选阈值，把它用于精投与准备阶段，收益远大于用于海投。

## 2. [hmjz100/LinkSwift](https://github.com/hmjz100/LinkSwift)
- **语言**：JavaScript
- **总 Star**：23,756
- **当日新增**：+538/天
- **简介**：基于 JavaScript 的网盘文件直链获取工具，从「网盘直链下载助手」改造而来，支持百度网盘、阿里云盘、中国移动云盘、天翼云盘、迅雷云盘、夸克网盘、UC 网盘、123 云盘共八家。
- **亮点**：它长期有人用的原因很朴素：各家网盘的 WebDAV/官方客户端体验参差，而拿到直链后就能塞进 aria2、IDM 或下载器里跑满带宽。工程上要注意这是典型的「依赖对方未公开接口」的方案——网盘侧一次前端改版或风控策略调整就会批量失效，所以升级要与自身使用绑在同一节奏上，别写进无人维护的生产脚本。合规边界也说清楚：抓自己账号下的文件属正常自用，用它批量转存、分发他人受版权内容或搭公开中转站则是另一回事，后者往往正是接口被封的原因。

## 3. [cursor/plugins](https://github.com/cursor/plugins)
- **语言**：TypeScript
- **总 Star**：11,982
- **当日新增**：+278/天
- **简介**：Cursor 官方的插件规范仓库，同时收录官方插件实现，定义了编辑器侧插件的打包结构与清单格式。
- **亮点**：这类「官方 spec 仓库」通常是判断一个生态成熟度的最好信号：说明厂商已经决定把扩展能力开放给第三方，并且愿意把格式冻结下来供人复现。对个人更实际的用途是照着官方插件反推写法——规则（rules）、命令、MCP 配置、子 agent 这些部件各自放在什么位置、如何声明依赖，比自己摸索文档快得多。需要留意的是插件规范本身仍在快速变动，跨版本兼容不保证，把内部知识沉淀成插件前先确认它绑的是稳定格式而非临时实现；另外第三方插件等于在自己的编码环境里装别人写的指令与脚本，安装前应读清单和实际内容，别只看下载量。

## 4. [android/skills](https://github.com/android/skills)
- **语言**：Kotlin
- **总 Star**：8,094
- **当日新增**：+36/天
- **简介**：Google Android 官方维护的 agent skills 仓库，把 developer.android.com 上的最佳实践写成一个个 AI 可执行的模块化指令（遵循 agentskills.io 的开放标准，即 SKILL.md 形式），且刻意只做「评测显示模型表现不佳」的窄场景，而不是重复覆盖 Jetpack Compose 这类模型本就熟练的通用知识。
- **亮点**：它的价值有两层。对 Android 团队，这等于把内部规范从「文档靠人自觉」变成「agent 执行时强制携带的上下文」，尤其是 R8 配置、内存泄漏排查、性能调优这类靠经验而非 API 记忆的活。对更广的工程视角，README 里那句「不优先做模型已经很擅长的领域」恰恰是目前 skill 设计最稀缺的判断准则——多数团队把 agent 技能库写成了 API 文档的副本，只对模型已经会的东西重复啰嗦，真正的收益应该来自评测暴露出的失败模式。落地时建议按自家事故清单挑选，配合版本化的 skill 与评测回放，观察是否真减少了返工，而不是先攒数量。
