## 1. [shiyu-coder/Kronos](https://github.com/shiyu-coder/Kronos)
- **语言**：Python
- **总 Star**：41,711
- **当日新增**：+363/天
- **简介**：专门面向金融市场「语言」的基础模型家族：一组 decoder-only 自回归 Transformer，预训练目标是 K 线序列而非通用时间序列。走两阶段路线——先用专用 tokenizer 把连续多维的 OHLCV 数据量化成层次化的离散 token，再在这些 token 上做自回归预训练，使单一模型可覆盖多种量化预测任务；模型按容量从 4.1M 参数的 Kronos-mini 往上分级，全部开放在 Hugging Face，并提供了微调脚本，论文已被 AAAI 2026 接收。
- **亮点**：它值得关注的地方不在「又一个时序预测模型」，而在把 LLM 那套范式认真搬到价量数据上：先用 tokenizer 显式建模金融数据的高噪声与量纲差异，再让 Transformer 只处理离散序列，这让「用大模型工具链做量化」的迁移成本一下变低，也留下了按自己品种/周期微调的入口。但要冷静看待：价格预测的信噪比远低于自然语言，回测收益极易被过拟合、幸存者偏差和前视信息放大，README 与 Live Demo 展示的是预测曲线而非可交易策略。真要接入，先用严格的样本外区间重跑，把交易成本、滑点与数据延迟算进去，并把它当作特征来源或对照基线——直接对接自动下单是最不建议的第一步。

## 2. [headroomlabs-ai/headroom](https://github.com/headroomlabs-ai/headroom)
- **语言**：Python
- **总 Star**：76,276
- **当日新增**：+310/天
- **简介**：一个「进模型之前先压一遍」的上下文压缩层：在工具调用输出、日志、文件内容和 RAG 召回分块抵达 LLM 之前先行压缩，官方给出的数字是编程 agent 场景少用 20% token、JSON 场景少用 60~95% token 而答案不变；同时提供库、代理（proxy）和 MCP server 三种接入形态，不要求改动业务代码。
- **亮点**：它切的正是 agent 成本结构里最实在的一块——上下文里绝大部分 token 其实是机器生成的中间产物（超长日志、重复字段的 JSON、整份文件），而不是人类可读的有效信息，这部分天然有压缩余地。以代理或 MCP 形式挂在现有 agent 与模型之间，是它落地成本低的原因，适合长日志排障、大 JSON 接口响应这类每次调用都灌几十 KB 的场景。风险同样来自「压缩即有损」：错误堆栈的行号、哈希、金额、时间戳这类必须逐字保真的字段一旦被摘要掉，模型会给出看似合理却错误的答案。上线前应对这些关键字段做保真校验，并把「答案不变」在自己的数据上重新测一遍，而不是直接采信宣传数字；压缩前后的响应延迟也要一并测量，否则可能省了 token 却赔了时延。

## 3. [withmarbleapp/os-taxonomy](https://github.com/withmarbleapp/os-taxonomy)
- **语言**：JavaScript
- **总 Star**：6,168
- **当日新增**：+284/天
- **简介**：Marble 开放的小学阶段「学什么」知识结构：把初等教育内容拆成 1,591 个细粒度 micro-topic，用 3,225 条先修（prerequisite）依赖边连成图，覆盖 8 个学科，并对齐各国课程标准；仓库附带可按年龄维度旋转查看的 3D 图谱可视化与在线交互版。
- **亮点**：教育数据常见的形态是一张扁平的知识点清单，只能用来打标签；它做的是把「学会 A 才可能学会 B」这一层显式建成图，于是「下一步该学什么」「这道题卡在哪个前置概念」第一次有了可复用的公共底座，自适应学习和题库知识点体系的冷启动成本会被显著压低。落地的两处约束要提前想清楚：一是课程标准有强地域差异，v1 对齐的纲目与本地大纲不能直接等同，用于生产前必须逐项核对，不能把这份图当作唯一真相；二是数据由商业公司发布，需确认许可证是否允许商用与再分发，以及后续版本由谁维护——把它当作可修改的对齐起点，而非长期依赖的权威源，是更稳的用法。
