## 1. [google/ax](https://github.com/google/ax)
- **语言**：Go
- **总 Star**：7,680
- **当日新增**：+2,305/天
- **简介**：Google 开源的 Agent 编排运行时（AX，Agent Executor），定位是一个高吞吐的声明式编排器，在集群上运行大规模自主 Agent 任务。用法与 Kubernetes 很像：用 YAML 声明 `Workspace`（比如挂一个 Git 仓库及其分支）和 `Task`（给出 goal 目标描述），`apply` 之后由 AX 负责创建沙箱、装配工作区、隔离网络并调度运行，`debug: true` 时还能直接 `ax ssh` 进沙箱观察 Agent 的执行过程。底层沙箱执行依赖下面榜单里的 Agent Substrate。项目自身标注仍处于快速演进阶段，稳定版之前会引入较大的破坏性变更。
- **亮点**：把「跑 Agent」写成了 `kubectl apply` 的心智模型——声明意图而不是编排进程，这是目前 Agent 基础设施里少见的、真正按云原生范式做抽象的实现，也是它一天涨两千多星的原因。

## 2. [dream-num/univer](https://github.com/dream-num/univer)
- **语言**：TypeScript
- **总 Star**：15,496
- **当日新增**：+255/天
- **简介**：面向「AI Agent 使用的 Office 底座」的全栈同构 Office SDK，可在自己的产品里嵌入电子表格、文档、演示、画布、关系型表格与 PDF。技术上由插件架构、Canvas 渲染、公式引擎和一整套 Facade API 组成，同一套 API 在浏览器和 Node.js 服务端都能跑；既能按插件粒度组合功能，也可用预设快速起步。核心 OSS 包以 Apache-2.0 授权，文档、Showcase 与 API Reference 齐全，并提供中文、日语、韩语、西语等多语言 README。
- **亮点**：卖点已从「开源的 SheetJS / Univer 替代 Office」升级为「给 Agent 一套可读写、可服务端执行办公软件运行时」，这正对上 AI 应用需要真实操作文档与表格的缺口。

## 3. [agent-substrate/substrate](https://github.com/agent-substrate/substrate)
- **语言**：Go
- **总 Star**：2,999
- **当日新增**：+245/天
- **简介**：Agent Substrate，一个默认安全的 Agent 执行运行时，目标是比标准容器运行时的密度高 10 倍地运行海量沙箱：恢复（resume）操作在 500ms 以内、每秒可完成 500 次以上的挂起 / 恢复，并内建零信任的内核与网络隔离，同时支持 microVM 与 gVisor 等多种沙箱技术。核心思路是把大量「actor」（Agent 类应用）复用到少量常驻 worker 上——因为 Agent 大多时间在空闲等待，以此实现超线程式的多路复用（官方 Demo 用 8 个物理 Pod 承载约 250 个有状态 actor）。它管理 actor 生命周期（创建 / 销毁、挂起 / 恢复）、实时分配与流量路由，底层复用 Kubernetes 做基础设施编排，且与框架无关：ADK、LangChain、Claude Code / Codex 等编码 Agent，以及作为长期运行 MCP Server 的工具都能托管。项目由 Google 团队发起但声明并非官方支持产品，目前处于早期开发阶段，API 不保证向后兼容。
- **亮点**：它回答的是 Agent 落地最贵的那个问题——海量有状态沙箱的成本。用「Agent 大部分时间在等 LLM 返回」这一事实换 30 倍以上的超卖比，思路接近 serverless 的冷启动优化，但对象换成了带内存和文件系统的 Agent。

## 4. [superdesigndev/treg](https://github.com/superdesigndev/treg)
- **语言**：Python
- **总 Star**：2,249
- **当日新增**：+230/天
- **简介**：自我定位为「工具版的 OpenRouter」——不是聚合模型，而是聚合 Agent 要用的外部工具。给 Agent 配置一个 base URL 加一个 token，即可调用目录中 60 多家服务商的 3,000 多个端点，覆盖 SEO 与外链数据、社媒与热点、人物 / 公司工商信息、广告投放、网页抓取、图像与视频生成等，按次计费、单次低至一分钱的零头，无需在各服务商分别注册。设计动机很直接：Agent 真正需要的数据源往往锁在 Semrush、Moz、Crunchbase、Apollo 这类月费几十到上百美元的订阅之后，或者干脆没有公开 API，而 treg 代为持有这些账号并按调用量拆分计费。除公共目录外还可注册团队自有凭据：一个 tool 是带凭据绑定的 endpoint，或直接注入凭据运行的厂商 CLI（`stripe`、`gh`、`vercel` 等），也可以用 `SKILL.md` + 密钥 + 工具打包成 skill；团队凭据始终优先于 treg 的凭据且不计费，密钥不出服务端。项目由 Superdesign 团队自用，线上服务在 treg.to，同时支持自托管。
- **亮点**：把「Agent 该调哪个 SaaS、账号从哪来」这件脏事先端收敛成一个 base URL，等于给工具调用补上了模型侧早已习以为常的计费与路由层——代价是关键凭据集中在服务端，自托管与否会是选型的核心问题。

## 5. [browser-use/video-use](https://github.com/browser-use/video-use)
- **语言**：Python
- **总 Star**：25,875
- **当日新增**：+191/天
- **简介**：用编码 Agent 剪视频。把原始素材丢进一个文件夹，在 Claude Code（也支持 Codex、Hermes 等任何有 shell 能力的 Agent）里对话，拿回一个 `final.mp4`，不依赖预设模板或菜单式时间线，口播、混剪、教程、旅拍、访谈均可用。具体处理包括：剔除「嗯」「啊」等语气词和 NG 片段与镜头之间的空白、对每段做自动调色（暖调电影感 / 中性高对比，或自定义 ffmpeg 滤镜链）、在每个剪辑点加 30ms 音频淡变避免爆音、按指定样式烧录字幕（默认两个词一组的 caps 字幕），并通过 HyperFrames、Remotion、Manim、PIL 派生并行子 Agent 生成动画叠加层。它会在把结果给人看之前先自行逐点评估渲染结果，并把会话记忆写进 `project.md` 供下次续接。安装方式是给 Agent 一段 setup prompt，由它自行完成 clone、ffmpeg 依赖、skill 注册和 ElevenLabs 转写密钥配置。MIT 协议。
- **亮点**：它把剪辑软件的能力拆成了 Agent 可自由组合的原子操作，而不是又一个套壳 ffmpeg 脚本；「先自评每个剪辑点再交给人看」这一步，是目前多数 AI 视频工具缺少的闭环。
