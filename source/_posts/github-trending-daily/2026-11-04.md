## 1. [floci-io/floci](https://github.com/floci-io/floci)
- **语言**：Java
- **总 Star**：28,850
- **当日新增**：+482/天
- **简介**：一个「轻、蓬松、且永远免费」的本地 AWS 模拟器，直接对标 LocalStack：`docker compose up` 或下载约 40 MB 的原生二进制就能在 `http://localhost:4566` 起一整套 AWS 兼容服务，不需要 AWS 账号、不需要 auth token、没有付费功能门槛，现有 AWS CLI / SDK / Terraform（用官方 HashiCorp AWS provider）凭证与区域照旧可用。README 按 8 大类列出了覆盖范围——核心应用（S3、SQS、SNS、DynamoDB、Lambda 及 Lambda MicroVMs / Web Functions、IAM、KMS、Secrets Manager）、事件与工作流（EventBridge 全系、Step Functions、CloudWatch）、API 与身份（API Gateway v1/v2、AppSync、Cognito）、容器与计算（ECS、EC2、EKS、MWAA、Batch、CodeBuild/Pipeline）、数据分析与 AI（Athena、Glue、EMR、Redshift、Flink、OpenSearch、Bedrock 与 AgentCore、SageMaker）、数据库与缓存（Aurora DSQL、RDS、Neptune、DocumentDB、ElastiCache、Timestream）、消息与传输（SES、Kinesis、MSK、MQ、Connect）、安全治理（Network Firewall、WAF v2、GuardDuty、CloudTrail、Organizations）；对Lambda、RDS、Neptune、ElastiCache、MSK、ECS、EC2、EKS、OpenSearch、CodeBuild、Flink 这些「装得像不像很关键」的服务走真实 Docker 执行而非浅层 mock。自带 Web 控制台（首次访问 `/_floci/ui` 时才按需拉起 `floci/floci-ui:0.7.0` sidecar），存储可选 in-memory / persistent / hybrid / WAL 四档持久度。
- **亮点**：本期最「名正言顺」的一次上榜——它的增长不是营销驱动，而是上游退场留下的空缺：README 直接写明 LocalStack 社区版已于 **2026 年 3 月停止维护**，改为要求 auth token 并冻结安全更新，floci 于是把「无缝替代」做成产品卖点：换镜像名即可，LocalStack 环境变量自动翻译，`/etc/localstack/init/` 下挂载的初始化脚本原样执行，`/_localstack/init` 与 `/_localstack/health` 两个端点仍然提供，甚至启动日志末尾会输出一行 LocalStack 风格的 `Ready`，好让 Testcontainers `LocalStackContainer` 的默认等待策略不用改一行代码就能继续工作。对比表里它给的数字也很具体：启动 ~24 ms vs ~3.3 s、空闲内存 ~13 MiB vs ~143 MiB、镜像 ~90 MB vs ~1.0 GB、许可 MIT vs 受限，且 API Gateway v2、Cognito、RDS/ElastiCache/MSK 等社区版本根本没有。今年 2 月 18 日才建仓、MIT、3,208 个 fork，最新 release 2.4.0 落在 10 月 15 日——九个月做到近 2.9 万 star，还有一处工程细节值得一看：控制台被定义成一份「console contract」（监听 `PORT`、实现 `GET /api/health`、用 `AWS_ENDPOINT_URL` 回连 floci），任何第三方面板改个镜像名就能替换，差异用 `io.floci.console.*` 镜像标签声明，社区里已经出现了 StackPort、Floci Dash 两个替代控制台。

## 2. [anomalyco/hex](https://github.com/anomalyco/hex)
- **语言**：Rust
- **总 Star**：4,620
- **当日新增**：+410/天
- **简介**：跨三平台的本地语音听写工具，交互只做一件事——按住快捷键、说话、松开，文字就直接粘贴进你当前所在的应用。转写全程在本机完成，只在首次运行时下载一次语音模型，之后「没有任何数据离开你的电脑」；实验性功能统一收在侧边栏底部的 Labs 里。安装渠道铺得很全：macOS（Apple 芯片）DMG、Windows x64/ARM64 安装包、Linux x86_64 与 ARM64 的可执行文件 / .deb / .rpm 都有稳定版和自动更新的 Dev 版，另有 `brew install --cask anomalyco/tap/hex`、AUR `yay -S hex-bin`、官方安装脚本和 `nix profile add github:anomalyco/hex` 四条包管理路径。
- **亮点**：今年 7 月 17 日建仓、MIT、默认分支是 `dev`，发布节奏快到有点夸张——`releases.atom` 里 10 月 20 日还是 2.3.1，10 月 31 日 3.1.0，11 月 1 日一天之内连发 3.1.2 与 3.3.0，十天跨过一个 minor 大版本。而它最不像常规开源项目的一句话在 README 结尾：**「We don't take pull requests」**——不接受外部 PR，只让贡献者开 issue，然后由「我们的 agents 通常很快把它做完」。在一个语音输入赛道里（同类项目普遍靠社区攒平台适配）直接把贡献入口关掉、把 issue 交给自家 agent 实现，是一次很直白的取向声明：宁可放弃分布式贡献换取发布速度与一致性。日增 410 占其总 star 的 8.9%，属于典型「刚被大量知道」的曲线，而非老仓库的回榜。

## 3. [Usagi-org/ai-goofish-monitor](https://github.com/Usagi-org/ai-goofish-monitor)
- **语言**：Python
- **总 Star**：16,475
- **当日新增**：+228/天
- **简介**：基于 Playwright 与大模型的多任务闲鱼监控与分析系统，带完整 Web 管理后台：任务管理、账号管理、AI 判断标准编辑、运行日志与结果浏览都在界面里做，支持用自然语言直接创建任务、用多模态模型深度分析商品，每个任务可独立配置关键词、价格区间、筛选条件与 Prompt，筛选能到包邮、新发布时间范围和省/市/区三级区域，命中后经 ntfy.sh、Gotify、Bark、企业微信、Telegram、自定义 Webhook 多渠道即时推送，并支持 Cron 周期性调度。反爬这一层做得比较实：多账号管理、任务绑定账号、代理池轮换与失败重试，还有一组 `TASK_FAILURE_THRESHOLD` / `TASK_FAILURE_PAUSE_SECONDS` 阈值熔断参数；触发风控时按 README 的流程图就是「账号/代理轮换并重试」。部署走 Docker 一键（`ghcr.io/usagi-org/ai-goofish:latest`，镜像内置 Chromium），主存储已迁到 SQLite（默认 `data/app.sqlite3`，启动时自动建库建表并从旧的 `config.json`、`jsonl/`、`price_history/` 迁移一次历史数据），最少只需配 `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL_NAME` 三项。
- **亮点**：2025 年 7 月 16 日建仓、MIT、2,851 个 fork，是这个榜单里少见的「国内需求原生 + 工程完成度高」的组合：它没有停留在爬虫脚本，而是补齐了后台 UI、多账号与代理轮换、熔断、Cron、通知矩阵和数据库迁移这些真正要长期跑起来才需要的部分，甚至专门写了「区域筛选默认建议留空，因为会显著减少搜索结果」这类使用层面的一手经验。仓库里也留着明确的边界：README 提示遵守闲鱼用户协议与 robots.txt、不要高频请求以免账号被限制，声明仅供学习与技术研究，并另附 `DISCLAIMER.md`；致谢部分点名参考了 `superboyyy/xianyu_spider`，也感谢 LinuxDo 社区与 ClaudeCode/Gemini/Codex 这类工具。最新 release 停在 2026-04-27 的 2.5，也就是说这次回榜靠的是持续传播而非新版本发布——对想认真用的人，值得注意的正是这条「半年没发版但仍在增长」的状态。

## 4. [spotify/portal-ai-plugins](https://github.com/spotify/portal-ai-plugins)
- **语言**：TypeScript
- **总 Star**：3,060
- **当日新增**：+91/天
- **简介**：Spotify 官方放出的 coding agent 插件包，把内部软件目录平台 [Spotify Portal](https://portal.spotify.com) 接进 Claude Code、Codex、Cursor 和 pi 四类 agent 环境，全部工作流都在包装上游的 `npx @spotify/portal-cli`：`setup` 配置认证、`doctor` 跑只读诊断（检查插件、CLI、认证与 action 就绪状态）、`search` 用自然语言搜软件目录与技术文档、`service` 生成包含归属、健康度、事故与文档信息的服务简报、`actions` 负责发现/查看/预览/调用 Portal action，另有 `feedback` 把意见直接回传给 Portal 团队，以及 5 个 `fleetshift-*` 工作流覆盖创建班次、触发并限时监控、只读查进度、诊断失败任务日志、为已完成的 target 开 PR——共 11 个命名工作流。安装是各 agent 的原生 marketplace 命令（`claude plugin marketplace add spotify/portal-ai-plugins` 等）。
- **亮点**：本期唯一由大厂官方账号发布、且专门面向「agent 操作内部平台」的仓库，两个细节比 star 数更有信息量。其一是安全设计：action 调用内置 `--help`、dry-run 与确认三道闸，`doctor` 被明确规定为只读，setup 会先校验 `auth`、`actions`、`owner`、`search`、`service` 五个命令齐不齐再放行——把「别让 agent 直接碰生产」写死在插件层。其二是随包附带的 **shunt**（暂只支持 Claude Code）：把批量读文件、生成模板代码这类 I/O 密集型工作，经 Portal actions registry 路由给 AiKA 模式下更便宜的 worker 模型跑，README 直接把它标为「token-saving」的可选安装项。这基本是大型公司内部平台团队对「agent 太贵」这个真实痛点的官方答案，值得当作同类私有平台接入的参考实现。今年 7 月 23 日建仓、Apache-2.0、239 个 fork，`releases.atom` 为空（从未发布过正式版本），说明它目前仍按 marketplace 直接分发的滚动模式在走；也提醒一点：GitHub 上该仓库描述为空（榜单 `desc` 同样为 null），本节简介完全取自 README 正文。
