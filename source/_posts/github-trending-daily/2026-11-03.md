## 1. [vercel-labs/agent-desktop](https://github.com/vercel-labs/agent-desktop)
- **语言**：Rust
- **总 Star**：9,937
- **当日新增**：+2,275/天
- **简介**：Vercel Labs 出品的「给 AI agent 用的电脑操作 CLI」：不让模型看截图猜坐标，而是直接读操作系统的无障碍树（accessibility tree），一次快照返回一份 JSON，里面给每个可操作元素配一个 ref，agent 对着 ref 下指令、再快照一次核对结果，全程无需像素匹配；以 CLI + C 库形式同时支持 macOS / Windows / Linux，`npm install -g agent-desktop` 即装，每次 CLI 调用跑在独立进程里。
- **亮点**：日增 2,275 是本期最高，且占到了总 Star 的 23%，而这个仓库今年 2 月才建仓、Apache-2.0 许可、10 月 30 日刚发布 v1.0.2——它抢的是「computer use」这条路上最实际的一个分歧点：视觉方案又贵又脆，无障碍树方案便宜且确定，README 里还专门写了安全边界（快照、剪贴板、屏幕截图都可能含桌面隐私内容，别丢进公开日志；会把屏幕描述发给模型服务商的 JEV helper 被拆成独立可选组件），这种把副作用讲清楚的写法在同类项目里不多见。

## 2. [D4Vinci/Scrapling](https://github.com/D4Vinci/Scrapling)
- **语言**：Python
- **总 Star**：92,978
- **当日新增**：+706/天
- **简介**：一个把「抓取全套件」收进单一库的 Python 网页抓取框架：快速 HTTP 请求、隐身浏览器、解析与选择器、并发爬虫（Spiders）、代理轮换和 CLI 都在同一个 API 面里，静态页直接取、需要渲染的走 `StealthyFetcher`，还能顺手提取页面背后的 API 调用；自带 MCP server 与 Agent Skill，让 AI agent 直接把它当浏览工具用。
- **亮点**：2024 年 10 月建仓、BSD-3-Clause，如今 9.3 万 star 配 9,788 个 fork，属于同类里少见的「既有量又有二创」的老选手；它回榜的节奏值得留意——最新 release v0.5 停在 10 月 17 日，也就是这次上榜靠前的是「一个库替代 requests + playwright + scrapy + bs4 选型成本」的口碑扩散，而不是刚发了大版本。

## 3. [JustVugg/colibri](https://github.com/JustVugg/colibri)
- **语言**：C
- **总 Star**：46,605
- **当日新增**：+675/天
- **简介**：口号是「tiny engine, immense model」——用纯 C 写的一个极小推理引擎，让普通机器跑上千亿甚至千亿级参数的 MoE 模型：MoE 每个 token 只激活模型的一小部分，于是 colibri 把这部分常驻内存，其余专家权重在模型需要时直接从磁盘流式读取，零依赖、不需要 GPU，一个模型家族一个文件。
- **亮点**：README 给的门槛与实测数字都很硬：最低 8 GB 内存（建议 16 GB+），最小的模型只要 22 GB 磁盘空间，一个 744B 参数的模型每 token 实际只用到约 40B（激活比例约 5.4%），示例里 32 秒就绪、常驻 9.9 GB；今年 7 月才建仓、Apache-2.0，10 月 31 日刚发到 v2.1.0，已支持 13 个引擎（10 个语言模型 + 1 个出图 + 2 个判别模型），并提供简体中文 README——它和下面的 FreeToken 一起构成了本期最值得注意的趋势：把「跑大模型」的瓶颈从显存改写成了磁盘带宽。

## 4. [FlashML-org/FreeToken](https://github.com/FlashML-org/FreeToken)
- **语言**：Python
- **总 Star**：16,105
- **当日新增**：+653/天
- **简介**：一个「边缘优先」的 MoE 推理服务引擎，目标是把数据中心级的开源权重大模型搬到个人与消费级硬件上（官方说法是在游戏 PC 上跑 290B+ 的前沿 MoE 模型并保持可交互速度）：把 GPU、CPU、主机内存和互联当作一个统一的弹性推理平台，用带宽自适应的 CPU–GPU 协同执行策略与整层双缓冲来喂饱计算，并支持在运行中动态重分配专家缓存与 KV 缓存所占显存而不必重启引擎。
- **亮点**：它比多数同类的杀手锏在接口上：对外提供 Anthropic / OpenAI 兼容 API，可被 Codex、Claude Code、OpenCode 等编码与工具调用 agent 直接接走，量化格式覆盖 MXFP4 / NVFP4 / FP8 / BF16，Windows 与 Linux 有带 GUI 的桌面端（flashml.ai），`uv pip install "freetoken[accel]"` 即可；项目挂着 arXiv 论文、Apache-2.0、7 月 20 日建仓，最新 release v0.2.1 在 10 月 30 日且另有 nightly 通道——已有正式论文 + 每日构建 + 中文社区（微信群），说明这是一支打算长期做基础设施的团队而非一次性 Demo。

## 5. [hyprwm/Hyprland](https://github.com/hyprwm/Hyprland)
- **语言**：C++
- **总 Star**：39,966
- **当日新增**：+509/天
- **简介**：一个完全独立开发的动态平铺 Wayland 合成器，主打「实用与好看我全要」：渐变边框、多种模糊、动画、光晕与阴影，动画曲线自研贝塞尔与弹簧模型；不基于 wlroots、libweston、KWin 或 Mutter，同时把插件能力做成一等公民（内置插件管理器）、提供易用的 IPC，并为游戏加入了 tearing 支持以降低延迟。
- **亮点**：作为 2022 年 3 月建仓、BSD-3-Clause 的老牌项目，它上榜靠的是持续迭代而非话题度——最新 release v0.57.0 发布于 10 月 28 日，几天内把一波升级用户推上趋势榜；3.9 万 star / 2,157 fork 的量级在 Linux 桌面工具里已经是头部，而它「拒绝复用 wlroots、自己写合成器」的技术路线选择，正是社区讨论度长期不降的原因：换来的是更强的动画与定制自由度，代价是所有底层硬骨头都要自己啃。

## 6. [p-e-w/heretic](https://github.com/p-e-w/heretic)
- **语言**：Python
- **总 Star**：38,130
- **当日新增**：+420/天
- **简介**：一套「免训练的大模型行为改造」工具，官方描述是「去除审查、抑制废话（slop）、降低谄媚（sycophancy）」，宣称在一个下午、用一台游戏 PC 就能完成：它不做昂贵的微调，而是用一组数学上的行为引导技术，靠成对的对照提示词与配套打分器来定位并改写模型的倾向，并默认按需做拒绝率优化。
- **亮点**：它真正的贡献是方法论——把「只有算力雄厚的大公司才能改模型」这件事降维成了配置文件的选择（默认 `config.default.toml` 就是拒绝抑制，另有 `config.noslop.toml`、`config.nosyco.toml`），还支持 bitsandbytes 的 4-bit 在线量化让模型塞进通常量化版的显存；AGPL-3.0、2025 年 9 月建仓、v2.0.0 刚在 11 月 1 日发布，3.8 万 star 与 4,326 个 fork 说明这条路线已经有相当规模的实践者。需要清醒看待的是：AGPL 的传染性、以及「移除安全约束后模型质量与滥用边界由使用者承担」这两点，决定了它更适合安全与对齐研究者的对照实验，而不是拿改造后的模型直接对外提供服务。

## 7. [kornia/kornia](https://github.com/kornia/kornia)
- **语言**：Python
- **总 Star**：12,148
- **当日新增**：+412/天
- **简介**：构建在 PyTorch 之上的可微分计算机视觉库，提供大批量、可自动求导、可 GPU 加速的图像处理与几何视觉算子——相机模型与标定、立体视觉与对极几何、单应估计、深度与视差、3D 变换、点云操作，以及能跟着几何变换一起走的图像增强；官方给出的方向是成为 PyTorch 生态里「可微分视觉与几何的参考实现与可执行规范」。
- **亮点**：这次回榜正好赶上 v0.9.0（10 月 23 日发布）；更值得读的是它把定位从「加 API」改成了「立规矩」——README 明写优先做显式约定、一致性测试与诚实基准，并直接贴出各模块在 float16/bfloat16 下的状态表（例如 `kornia.augmentation` 存在容器 autocast 运行时错误与精度问题、3D 反向传播与随机数生成器精度待验）。这种自曝短板的写法对使用者反而是最有用的信息，也是老牌库（2018 年 8 月建仓、Apache-2.0、1,490 fork）在 PyTorch 官方算子越来越全的今天维持差异化的办法。

## 8. [paperclipai/paperclip](https://github.com/paperclipai/paperclip)
- **语言**：TypeScript
- **总 Star**：110,426
- **当日新增**：+412/天
- **简介**：一个面向「工作场景」的开源 AI agent 管理应用，自己的说法是「如果 OpenClaw 是一名员工，Paperclip 就是那家公司」：由 Node.js 服务端 + React 界面组成，用来编排一支 agent 团队——接入你自己的 agent、分派目标、在一个仪表盘里追踪工作与成本，每个 agent 可各自选模型与执行环境，而团队的任务、技能、权限与历史统一留存在一处。
- **亮点**：它把「多 agent 编排」这个抽象词翻译成了管理者看得懂的两层结构：一层是「agent 组织架构图」（角色、职责、委派关系、人类与 agent 混合编排、密钥作用域与连接权限），一层是「Agentic OS」（跨供应商运行时、沙箱与 MCP 集成、SSO / RBAC / 成本管控与审计）；成本侧支持公司、agent、项目三级预算与阈值告警并在超限暂停工作。MIT 许可、11 万 star 之外还有 18,282 个 fork（本期最高，甚至超过 star 增长暗示的热度），release 用日期版本（最新 v2026.1023.0，10 月 24 日）、另有 Paperclip Cloud 候补名单——fork 数远超同量级项目通常说明企业与团队在拿它自建，而不只是围观。

## 9. [karpathy/nanochat](https://github.com/karpathy/nanochat)
- **语言**：Python
- **总 Star**：59,920
- **当日新增**：+321/天
- **简介**：Andrej Karpathy 做的「最简单的 LLM 训练实验台」：代码刻意保持精简可改，覆盖分词、预训练、微调、评估与推理全流程，在一台单 GPU 节点上就能跑通；典型用法是花约 48 美元（8×H100 跑两小时）训练出一个能力对齐 GPT-2 的模型并用命令行对话，用竞价实例则能压到约 15 美元——而 2019 年训练 GPT-2 花了约 4.3 万美元。
- **亮点**：它最有教学价值的工程设计是「一个复杂度旋钮」：只设 `--depth`（层数，GPT-2 能力大约对应 26 层），宽度、注意力头数、学习率调度、训练时长、权重衰减等全部超参按最优规则自动推出，从而一整套 compute-optimal 小模型系列共享同一份配置逻辑；评价指标也收敛成一个——「time to GPT-2」（在 8×H100 上超过 GPT-2 1.6B 的 CORE 0.256525）。MIT 许可、2025 年 10 月建仓、5.9 万 star / 8,414 fork，且不发 GitHub release（走 main 直接演进）。README 还把落地门槛写得很实：单卡不跑 `torchrun` 会自动切梯度累积、显存不足 80GB 时需要逐级调小 `--device-batch-size`。

## 10. [max-sixty/worktrunk](https://github.com/max-sixty/worktrunk)
- **语言**：Rust
- **总 Star**：10,062
- **当日新增**：+77/天
- **简介**：一个专为「并行跑 AI 编码 agent」设计的 Git worktree 管理 CLI：worktree 本身强大但难用，它用三条核心命令把 worktree 变得和分支一样简单（`wt list` / `wt switch` / `wt remove` / `wt merge` 一组动词式命令），再补上一层质量提升——用钩子自动化本地流程、用写时复制（copy-on-write）构建缓存避免每个 worktree 从零重建。
- **亮点**：日增 77 是本期最低，属于稳态长尾而非爆发；但作者 11 月在 README 开篇写明它年初发布后「很快成了最流行的 git worktree 管理器」，节奏上也保持得不错（最新 v0.81.0，10 月 20 日发布）。需要留意的是许可：GitHub 的 SPDX 识别结果是 Other / NOASSERTION，而仓库徽章写的是 MIT OR Apache-2.0 双许可，商用集成前建议以仓库 LICENSE 文件为准。它解决的问题很具体——多个 agent 同时改代码时，最大的摩擦不是模型而是同一份工作目录的互相干扰，worktree 隔离 + 增量构建缓存正好是这一环的工具。
