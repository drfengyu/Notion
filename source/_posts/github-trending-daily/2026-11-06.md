## 1. [microsoft/VibeVoice](https://github.com/microsoft/VibeVoice)
- **语言**：Python
- **总 Star**：55,991
- **当日新增**：+223/天
- **简介**：微软放出的开源「前沿语音 AI 模型家族」，TTS 与 ASR 两条线一起开源。它的核心创新是帧率只有 **7.5 Hz** 的连续语音 tokenizer（分声学与语义两路），在保住音质的同时把长序列的计算量压下来，再用 next-token diffusion 框架分工：LLM 负责理解文本上下文与对话流，diffusion head 负责生成高保真的声学细节。当前共五个权重：VibeVoice-ASR-7B 把 **60 分钟长音频一次性单遍**转写为「谁（说话人）· 何时（时间戳）· 说了什么（内容）」的结构化结果，即 ASR、说话人分离与时间戳三件事联合完成，支持用户自定义热词（人名、术语、背景信息）来拉高领域内准确率，原生多语覆盖 50 余种语言；ASR-Streaming（2026-09-03）是统一流式识别版本，音频还在进来就持续出字、按块发射文本，支持热词与 10 种语言；ASR-BitNet（2026-07-23，配套 `microsoft/VibeASR.cpp`）是边缘 CPU 推理引擎，用 I8_S + I2_S 异质量化把模型从 4.62 GB 压到 1.58 GB，3 个以上 CPU 线程就能做到 RTF < 1，完全不需要 GPU；VibeVoice-TTS-1.5B 是长对话合成模型，单遍可生成最长 **90 分钟**、最多 **4 个说话人**的音频，保持跨长对话的音色一致与语义连贯，论文被 ICLR 2026 接收为 Oral；VibeVoice-Realtime-0.5B 是轻量实时 TTS，支持流式文本输入、约 300 ms 的首个可闻延迟、单次约 10 分钟的稳健长语音，2025-12-16 起为它补充了九种语言（德、法、意、日、韩、荷、波、葡、西）的实验音色与 11 种英文风格音色。使用侧给得很齐：ASR 有 Gradio Playground 与 Colab，支持 vLLM 服务化（`docs/vibevoice-vllm-asr.md`）与流式服务化，ASR 微调代码放在 `finetuning-asr/`，TTS 与 ASR 的技术报告各有 arxiv / OpenReview 链接，权重集中在 Hugging Face 的 microsoft collection。
- **亮点**：三处反差最值得记录。其一，**这个仓库今天的招牌能力并不是它最热的那条线**：README 在 2025-09-05 的更新里写明，发布后发现了与「推动语音合成社区协作」这一意图不符的使用案例，出于微软「负责任 AI」的原则已**把 VibeVoice-TTS 的代码从仓库中移除**，模型表格里 TTS-1.5B 的 Quick Try 一格直接是 Disabled，但 TTS 的论文、结果图与五段 demo 视频（含中英跨语与「自发歌唱」）仍完整留在页面上——「撤下实现、保留论文与权重」这种半开源形态，是近年前沿语音模型里越来越常见的处置方式。其二，许可与用途声明的张力：仓库本身是 MIT（`spdxId: MIT`），可 Risks and Limitations 段落同时写着「不建议在没有进一步测试与开发的情况下用于商业或真实场景，本模型仅供研究与开发使用」，并明确点名高保真合成语音在冒充、欺诈与虚假信息上的滥用风险、要求使用者披露 AI 生成内容，还坦白模型会继承基座（本次发行版本为 Qwen2.5 1.5B）的偏差与错误——对国内团队来说，「MIT 就等于能直接商用」这个直觉在这里需要多读一段。其三，**这次上榜和发版、和提交都无关**：`releases.atom` 条目数为 0、`sidebarAbout` 的 releaseCount 与 tagCount 也都是 0，`commits.atom` 的最后一次提交停在 2026-10-08（约四周前），也就是说 +223 是纯传播驱动的回榜；而它 2025-08-25 建仓、6,300 个 fork 对 268 个 watcher（约 23:1）的比例远高于一般研究仓库，配合上面那套微调与 vLLM 服务化文档，说明真正把它跑起来做实验的人相当多。

## 2. [ConardLi/garden-skills](https://github.com/ConardLi/garden-skills)

- **简介**：面向 Claude Code、Cursor、Codex 等 AI 编码 agent 的生产级 Agent Skills 精选合集，共 6 个 skill，README 有英 / 中 / 日三语版本。它的基本单位是「自包含文件夹」：一个必需的 `SKILL.md`（YAML front-matter + 指令）加上可选的 `references/`（按需展开的长文档）、`scripts/`（确定性可执行辅助）、`assets/`（模板、字体、图标），遵循 agentskills.io 的规范，agent 完全依据 front-matter 里的 description 决定要不要启用——README 把这句话说成「你和 agent 之间的契约」。六个 skill 分工明确：`motion-showreel`（Motion Graphics / Code Video）交付 MP4 加可编辑源，短片通常 5–60 秒、章节式长片支持到 20 分钟，做法是先确认主题、时长、画幅、独立的音乐/SFX 来源与旁白模式，写 brief 并确认风格帧，然后用确定性的 `render(t)` 页面在共享的音画时间线上逐帧捕获，静帧、contact 3D、像素游戏、国潮纹样、手稿彩饰等）；`web-video-presentation` 把讲稿、文章、课程、产品演示、演讲转成点击驱动的 16:9 Web 演示再录成视频，固定 1920×1080 舞台按视口缩放、以 (chapter, step) 光标推进且一步对应一句旁白、悬停才显示的进度控件保持录制画面干净，23 套内置主题各带自己的设计签名，TTS 是可插拔的 没有工具时的纯提示词顾问）且每个任务先做模式检测以免选错执行路径，收录 18 个视觉类别与 79 个结构化提示词模板，Garden 模式下提示词与成图归档在 `garden-gpt-image-2/` 便于复用与版本化；`beautiful-article` 把 URL、PDF、DOCX、Markdown、纯文本、截图、粘贴笔记编辑成「更易读、易分享、易归档的成稿」而不是 merely ## 3. [vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser)
- **语言**：Rust
- **总 Star**：45,938
- **当日新增**：+150/天
- **简介**：Vercel Labs 出的 AI agent 浏览器自动化 CLI，原生 Rust 单命令，核心约定是「一条命令走一步」：`snapshot -i` 把页面压成带 `@e1` 这类 ref 的紧凑文本，agent 对着 ref 执行 click / fill / press，然后重新读页面确认结果，如此循环；浏览器在命令之间保持打开，所以每一步都只是一次很短的 shell 调用。实现上它把每条命令转发给一个首条命令时自启的后台 daemon，daemon 通过 Chrome DevTools Protocol 控制浏览器，每个 `--session` 拥有独立的 daemon 与浏览器实例；配置了会话持久化时，无头浏览器在一小时无命令后会先保存状态再退出。默认浏览器是 Chrome for Testing，另外可以用 `--cdp` / `--auto-connect` 附着到已在运行的 Chrome（CDP 模式），用 `--engine` 切换 Lightpanda 或 Obscura 引擎，在 iOS Simulator 里驱动 Mobile Safari，或接 Browserbase、Browserless、Browser Use、Kernel、AgentCore 等云浏览器提供方。命令面按十组整理：导航与读取（`open` `back` `forward` `reload` `read` `snapshot` `get` `is`）、交互（`click` `dblclick` `fill` `type` `press` `keyboard` `hover` `focus` `select` `check` `uncheck` `scroll` `drag` `upload` `mouse` `find`）、等待、捕获（`screenshot` `pdf` `record` `download` `diff`）、页面与网络状态（`cookies` `storage` `network` `set` `clipboard` `eval` `pushstate`）、标签页/iframe/对话框、调试与性能（`console` `errors` `highlight` `inspect` `trace` `profiler` `vitals` `react` `a11y`）、会话与鉴权（`session` `state` `auth` `profiles` `confirm` `deny`）、agent 与集成（`skills` `mcp` `webmcp` `flow` `chat` `batch` `plugin`）、观测（`stream` `dashboard`）与安装运维（`install` `upgrade` `doctor` `connect` `close`）。定位器除 ref 外也支持 CSS 选择器、文本、XPath 与语义定位；分发覆盖 macOS（ARM64/x64）、Linux（ARM64/x64，glibc 与 musl）、Windows（x64），npm 包按宿主挑二进制，也可 `brew install`、Linux 用 `--with-deps` 连带装浏览器系统库、或干脆 `npx agent-browser open example.com` 不装；`agent-browser mcp` 能起一个 stdio 的 MCP server。源码构建需要 Node.js 24+、pnpm 11+ 与 Rust，Rust 侧检查用 `cargo fmt --check`、`clippy`、`cargo test`（e2e 会真起无头 Chrome）。
- **亮点**：它对「skill 会和 CLI 版本漂移」这个问题的解法最值得单独抄出来：CLI 自带 `agent-browser skills get core`（还能 `--ref commands` 只取一份参考、`--full` 附上完整命令表与模板，另有 electron、slack、dogfood 等专项 skill），而 `npx skills add vercel-labs/agent-browser` 装进 harness 的只是一个**很薄的发现型 stub**，内容就是「先跑 `agent-browser skills get core` 再照着做」，于是给 agent 的指令永远与本机安装的 CLI 版本一致；也可以直接把这句话写进 `AGENTS.md`。这与同一天在榜的 garden-skills「把版本化产物钉在文档里」正好是两条互补路线。第二个信号是迭代密度：`releases.atom` 显示 v0.41.2 与 v0.41.1 都落在 2026-11-03，v0.41.0 在 11-01、v0.40.0 在 10-29，v0.39.1→v0.39.4 在 10-22 至 10-27 之间连发四个补丁，累计 120 个 release 对应 2026-01-11 建仓后约十个月，也就是平均不到三天一个版本，`commits.atom` 的最后一次提交就在昨天（2026-11-05 21:14）。第三，安全面没有留白：文档单列 Security 页，把 auth vault（凭据库）、domain allowlists、action policies、content boundaries 做成一等能力，命令里也有 `confirm` / `deny` 一对——把「agent 驱动真实浏览器」的授权边界写进 CLI，而不是留给调用方自己兜。数据面：Apache-2.0、3,150 个 fork 对 101 个 watcher，今日 +150 只占存量 star 的 0.3%，属于大存量工具的稳态回榜；同日榜单里另有同组织的 agent-desktop（+2173）在榜，但那是往期间已推送过的仓库，故本期只收这一条。
