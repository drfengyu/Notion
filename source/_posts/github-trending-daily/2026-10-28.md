## 1. [HKUDS/DeepTutor](https://github.com/HKUDS/DeepTutor)
- **语言**：Python（Python 3.11+ 后端 + Next.js 16 前端）
- **总 Star**：46,029
- **当日新增**：+1,598/天
- **简介**：港大 HKUDS 实验室的「agent-native 学习工作台」，口号是 Lifelong Personalized Tutoring，配 12 种语言 README 和 arXiv 论文（2604.26962）。它的做法不是做一个「AI 家教聊天框」，而是把学习动作拆成十种共享同一运行时与会话上下文的能力模式：Chat、Ask Questions、Quiz、Research、Visualize、Solve、Course Study、Mastery Path、Immersive Reading、Audio Overview，各模式保留自己独立的循环与流水线。上下文侧可挂知识库、书籍、Co-Writer 草稿、笔记本、题库、persona 与 Memory，并在这些模式之间复用；知识引擎是可插拔的多后端——LlamaIndex、PageIndex、GraphRAG、LightRAG（含原生角色模型：抽取/查询/视觉三套配置可分开）、远端 LightRAG Server、自托管 WeKnora、腾讯 IMA 或 MarginNote 4 书库、Kiwix ZIM 归档、直连 Obsidian 库。个性化用的是可检查的三层记忆：L1 原始轨迹、L2 表层摘要、L3 综合结论，并用 Memory Graph 把 L2 事实回连到 L1 证据、把 L3 连到其来源表层，全程可见可编辑。工具面走 MCP server + CLI 应用 + 图像/视频/语音生成模型 + EduHub 社区技能；另有 Task Board（To do / In progress / Done，可拖拽、可归档还原，不需要模型配置）、沉浸式视频学习（YouTube / Bilibili 链接进 Reading，原生播放、字幕检索、按时间戳讲解、笔记与断点续读），以及 Subagents / Partners——从 Chat 里直接调用一个活的编码 agent harness（Claude Code、Codex、Grok CLI、Antigravity、Kimi、opencode、MiMo、Hermes、OpenClaw、DeepSeek）或 Partner，导入历史会话，同一套「大脑」上跑常驻 IM 伴学。对 agent 友好的关键设计是那个单一 `deeptutor` 二进制：人用 `deeptutor chat` 开 REPL，机器用 `deeptutor run <capability> "..." --tool --kb --config --workspace`，加 `--format json` 后每一轮以 NDJSON 逐行吐事件（`content`/`tool_call`/`tool_result`/`done`，每行带 `session_id`），无 TTY 时 `ask_user` 暂停会自动以空回复放行而不是挂死。README 甚至建议你把一段安装提示词直接丢给 Codex / Claude Code，让它读 `docs-for-user/AGENT_SETUP.md` 替你装好并起 Web 服务。2025-12-28 创建，Apache-2.0，5,769 个 fork，最新提交停在 2026-10-18（README 顶部标注 v1.6.15 发布于 10-19）。
- **亮点**：值得抄的是两条工程决策。其一是把「个性化」做成可审计数据结构而不是塞进 prompt——L1/L2/L3 分层加 Memory Graph 让「它为什么这样教我」可点开看证据链，这比大多数记忆方案只写一段摘要要负责得多；其二是 NDJSON + headless 自动放行，说明作者真把它当成别人的 agent 会调用的工具来设计接口，而不是只做 GUI。要付的代价也很清楚：依赖面极宽（RAG 后端就列了七种，外加 Next.js、Docker、各类解析引擎和多个模型供应商），首次跑通的成本主要花在配供应商密钥而不是读代码；发布节奏从 8 月底 v1.6.1 一路到 10 月中 v1.6.15，六周十几个版本，功能仍在高频重塑期，升级时按「每次都可能动到配置与数据结构」来准备。另外它是学术研究组的项目而非产品公司，README 里的能力清单与论文口径一致但缺独立的性能评测，教学效果的「个性化」宣称需要自己拿材料验证。

## 2. [elayadesign/ai-design-skills](https://github.com/elayadesign/ai-design-skills)
- **语言**：无（纯 Markdown，无可识别主语言）
- **总 Star**：9,489
- **当日新增**：+1,395/天
- **简介**：面向 AI 编码工具的「设计技能」合集，定位是给 Claude Code、Cursor、Codex、Windsurf 以及任何会读一个 markdown 规则文件的工具用；每个技能是一个自包含文件夹，按需装你要的那几个。当前仓库里实际只有 **1 个**技能 `landing-page-design`：从零起一个落地页，走「先问 intake 问题 → 定页面结构 → 写转化文案 → 补一整套视觉系统（字体、间距、圆角、动效）」的路子。安装方式按工具分成四条：Claude Code 是 clone 后把 `skills/<skill-name>` 拷进 `.claude/skills/`；Cursor 用 curl 把 `SKILL.md` 拉成 `.cursor/rules/<skill-name>.md`，或直接粘进 Settings → Rules for AI；Codex / Windsurf / Cline 分别对应 `AGENTS.md`、`.windsurfrules`、`.clinerules`，通用做法是粘进 system prompt；没有终端就下载 `SKILL.md` 上传到 Claude.ai 的 Project，或附在对话里说一句「follow this」。它有一个很实在的设计约定：每个技能的设计取值（字体、颜色、间距、动效）集中在文件底部的一节里，fork 之后只改那一节，技能其余部分自动跟着走。归属上 MIT（「用、fork、发布、卖你用它造出来的东西」，无需署名），并注明 `landing-page-design` 的「文案真实感」和动效思路改编自 Leonxlnx/taste-skill（同为 MIT）；README 还指向同作者的另一个仓库 `redesign-skill`——「改造已有站点而不是新建」的技能因为早于这个合集，单独放着。2026-07-29 创建，679 个 fork，最新提交 2026-10-27。
- **亮点**：一个近万 star 的仓库实际只装了一个 markdown 文件，这个比例本身说明需求侧的饥渴——大家都在给 agent 补「审美与版式」这块短板，而供给侧几乎没有像样的东西。真正能搬走的是「设计 token 收在文件末尾单一小节」这一条：把可变量集中、把方法固定，技能才能被不同人 fork 后各长各的样子，否则每个团队的技能都会互相污染。用的时候注意两个偏差：一是「合集」目前尚名不副实，`More on the way` 还没来，跨技能选型得连 `redesign-skill` 一起看；二是它给的是结构与流程约束，输出质量仍取决于底层模型的视觉能力，别指望一份 SKILL.md 把不会排版的模型变成设计师。

## 3. [togg53192-cmd/jailbreaks](https://github.com/togg53192-cmd/jailbreaks)
- **语言**：无（Markdown 与文本文件，共 38 个文件）
- **总 Star**：5,633
- **当日新增**：+902/天
- **简介**：仓库名直白叫「LIST OF ALL MY JAILBREAKS」，README 自述是一份「针对 25+ 个模型的 31 条可用提示词」的合集，形态包括完整 system prompt、persona 定义、workspace policy、`AGENTS.md` 文件、配置块以及 Ollama Modelfile，并强调每个文件都是「完整、可直接粘贴」的，不放摘要也不截片段。覆盖面分三类：通过 OpenCode Zen 提供的「免费隐藏模型」、开源权重家族（GLM、DeepSeek、Kimi、Qwen、Gemma、GPT-OSS）、以及闭源前沿模型（Claude、Gemini、Grok、Mistral）。用法也按载体分：system prompt 贴进客户端或 API 的 system / 自定义指令字段；`AGENTS.md` 放到仓库或工作区根目录，让编码 agent 当作项目级指令读取；标着「assistant operating specification / workspace operating profile」的文件用于支持工作区级策略的环境；另有 Ollama Modelfile 与 Grok 专用配置。作者在 README 顶部放了 WARNING、末尾放了 Disclaimer：声明仅作研究与教育用途，项目的目的是文档化「指令层级、persona 框架、提示词冲突、策略边界」这些行为，也可用于帮助开发者加固系统以抵御 prompt injection 与指令操纵，同时写明维护者不认可违法、滥用或有害的使用。2026-06-18 创建，834 个 fork，最新提交 2026-10-25；仓库**未声明任何 LICENSE**。（本报告只描述其结构与用途，不收录、不转写其中任何提示词原文。）
- **亮点**：对做 agent 安全的人，它的实用价值在于这是一套现成的、按模型家族分门别类的红队输入集：与其读 prompt injection 的论文再自己造样本，不如直接拿这些文件去问「如果我把一份陌生 `AGENTS.md` 放进工作区，我的 agent 会不会因此放开工具权限、改变审批策略、或泄露上下文」——它的存在本身就是这类项目级指令通道有多好劫持的证据。风险同样是三层：无 LICENSE 意味着默认保留所有权利，直接再分发、打包进产品或镜像到内网仓库都不安全；内容是第三方模型提示词的收集，来源与真实性均不可验证，指望它「解锁」某个付费模型的能力更多是营销叙事；而它教的攻击面正是你把它跑起来时自己要面对的——把陌生人的指令文件放进 agent 可读路径，等于把项目级指令权交给外人。真要研究，建议在隔离环境里做输入侧实验，只观察行为差异，不要接入任何有真实凭据或生产数据的工作区。
