## 1. [Alishahryar1/free-claude-code](https://github.com/Alishahryar1/free-claude-code)
- **语言**：Python
- **总 Star**：59,195
- **当日新增**：+626/天
- **简介**：把 Claude Code、Codex、OpenCode、Pi 以及 VSCode 等多个「AI 编码外壳」统一接入一组免费模型额度的网关项目，README 宣称已累计提供 13 亿+ 免费 token，可从终端、App、IDE、手机使用，最近还加入了浏览器原生会话；同时强调「多外壳 + 多模型」、支持语音，并自称走的是 ToS friendly（不违反服务条款）的路线。
- **亮点**：真正值得看的不是「免费 token」，而是它被迫解决的那层适配问题：各家 agent 的 tool-call 格式、系统提示约定、流式协议互不兼容，能把它们收敛成一个统一的 OpenAI 兼容端点，这份仓库基本等于一份现成的兼容性对照表，自己写 MCP 网关或模型切换器时可以直接抄它的分派逻辑。风险也要讲清楚：额度来源是第三方渠道，可用性与存续期都不在你控制范围内，README 里的 ToS 声明更不是法律结论——用于学习、原型与个人效率没问题，放进生产链路或团队默认工作流，就要自己承担突然中断与合规争议的后果。

## 2. [mksglu/context-mode](https://github.com/mksglu/context-mode)
- **语言**：TypeScript
- **总 Star**：27,344
- **当日新增**：+246/天
- **简介**：面向 AI 编码 agent 的上下文窗口优化层：把工具输出先放进沙箱执行、只把摘要送回主上下文（宣称压缩掉 98% 的 token 占用），另存可寻址的原始结果并持久化会话记忆，再通过 MCP + hooks 在 17 个平台上强制统一的模型路由策略。
- **亮点**：它打的是当前 agent 工作流最实在的痛点——一次 `grep` 或构建日志动辄几万 token，长会话很快就退化成「记不住前面在干什么」。可以直接复用的思路是「原始输出不进主上下文，只留引用」：把全文丢到外部存储，上下文里只保留一个能回查的句柄，需要细节时再按需取。但「98%」这类数字强依赖摘要与采样策略，一旦把排错关键的那几行压掉了，损失的时间会比省下的 token 贵得多；落地时按工具类型分别配置压缩规则（日志/差异可激进摘要，补丁与报错栈保留原文）比一刀切更稳。

## 3. [open-webui/open-webui](https://github.com/open-webui/open-webui)
- **语言**：Python
- **总 Star**：155,071
- **当日新增**：+157/天
- **简介**：自托管的多模型 AI 对话界面，对接 Ollama、OpenAI API 及各类 OpenAI 兼容端点，带 RAG 文档问答、工具/插件、多用户与权限、语音与图像生成等能力，是私有化部署聊天前端里事实标准之一。
- **亮点**：它能长年在榜说明需求非常稳定：模型会一直换，团队要的是一层管住密钥、用户和文档权限的前端。选型时的真实成本不在功能而在运维面——自托管就要跟上它的 CVE 与升级节奏；上线前至少确认默认管理员密码已改、注册被关闭、RAG 索引的文件访问范围和内网端点做了隔离，否则一个「内部 AI 门户」很容易变成对内网可读的入口。

## 4. [microsoft/BitNet](https://github.com/microsoft/BitNet)
- **语言**：C++
- **总 Star**：40,934
- **当日新增**：+97/天
- **简介**：微软 1-bit 大模型（BitNet b1.58，权重取 -1/0/+1 三值）的官方推理框架，提供针对三值权重的 kernel 与完整执行链路，支持把 Hugging Face 权重转成自定义格式，在 CPU 与消费级设备上以显著更低的内存占用和能耗完成推理。
- **亮点**：它的意义在于把量化从「部署后的优化」提前成「训练时的假设」：权重只剩三值后，矩阵乘退化成加法与查表，显存与带宽压力大幅下降，端侧与 CPU 推理的性价比曲线被改写。不过要区分两件事——仓库定位是研究性推理内核，官方并不标注为生产就绪；三值化在质量上仍有代价，长上下文与复杂推理的退化需要自己评测。对打算做 CPU 推理的团队，最实用的收获是它的算子组织方式与权重格式设计，而不是「直接拿来上线」。
