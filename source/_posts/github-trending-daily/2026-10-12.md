## 1. [bilawalsidhu/gods-eye-view](https://github.com/bilawalsidhu/gods-eye-view)
- **语言**：JavaScript
- **总 Star**：51,832
- **当日新增**：+886/天
- **简介**：作者那支播放量 500 万+ 的「God's Eye View」系列视频背后的项目（前作 WorldView），今年 8 月曾登顶 GitHub Trending 日榜与周榜。它是一个跑在浏览器里的「间谍卫星模拟器」——只不过所有数据源都是公开的实时信号：飞机应答机、船舶 AIS、卫星轨道根数、地震台站、公开摄像头，叠加在一个照片级真实的 3D 地球上。功能包括坐进被追踪航班视角的 Cockpit view、以目标为圆心 250 km 的邻接目标清单、点击即锁定并绘制拖尾轨迹、语音实时标注（可直接在世界图上说出边界多边形、标记与航线）、按机型加载真实 3D 模型（787、ATR-72、Citation、Bell 206、MQ-9），以及用 GLSL 着色器做的红外/传感器风格滤镜。README 明确标注了哪些是近似：交通是沿真实道路用聚合位置数据模拟的，摄像头朝向与火箭发射轨迹是粗估。本地即可启动、无需 API key，可选密钥在应用内补填。
- **亮点**：这类项目真正的门槛不在图形，而在「多源异构实时数据的接入与对齐」——ADS-B、AIS、TLE、地震波形各有各的刷新频率、坐标系与延迟特性，能把它们统一到一个可交互时间轴上并保留来源标注，是工程量的大头。它的诚实也值得留意：把「哪些是实测、哪些是模拟」写进 README，而不是靠视觉真实感蒙混——这对做态势感知、舆情/灾害可视化的人是可直接复用的分层架构（每个图层是独立模块，可自行扩展接自己的数据源）。风险面同样清晰：把公开数据聚成一张可下钻到街景的地球，本身就是一个需要严肃对待的隐私与滥用议题。

## 2. [lyogavin/airllm](https://github.com/lyogavin/airllm)
- **语言**：Jupyter Notebook
- **总 Star**：36,565
- **当日新增**：+548/天
- **简介**：主张「AirLLM 70B 推理只需单张 4GB 显存」的开源推理框架。思路是不再把整个模型权重常驻显存，而是按层从内存/磁盘流式加载，配合对层级并行与预取的调度，让消费级显卡甚至无显卡环境也能跑 70B 级模型；项目长期以 notebook 形态提供开箱即用的演示，定位是把「大模型必须在 A100 集群上跑」这个前提拆掉。
- **亮点**：需要当成「权衡」而不是「银弹」来读。把权重搬运的成本从显存换成 PCIe/内存带宽后，换来的是能跑，代价是首 token 延迟与吞吐显著变差——它对单次交互式推理、原型验证、教学演示很划算，对高并发服务化则通常不划算。真正值得注意的是它对层的加载顺序与预取策略：这套调度思路可以直接搬进任何 MoE 或超长上下文服务里，做「按专家/按层的热度分级驻留」，这部分比「70B on 4GB」的口号更有复用价值。
